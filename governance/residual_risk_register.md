# Residual Risk Register

| Risk | Severity | Status | Owner | Control | Residual risk |
| --- | --- | --- | --- | --- | --- |
| Heuristic redaction misses uncommon PHI formats | High | Open | Privacy | Regex redaction, policy block, redaction benchmark with gated email/phone/SSN/member ID recall | Requires managed sensitive-data inspection before production; bare-name and bare-date recall are tracked but non-gated limitations |
| Heuristic redaction over-matches (false positives), e.g., a 10-digit provider NPI masked as `[PHONE]` | Medium | Mitigated | Privacy/Engineering | Phone pattern requires phone-style formatting (separators/parentheses); provider identifiers (NPI/TIN) are out of scope and left visible; redaction unit tests cover both directions | Production requires managed sensitive-data inspection with typed entity labels rather than coarse regex categories |
| Raw PHI persists in ADK session state, history, or platform logs before model-request redaction | High | Open | Privacy/InfoSec | Pre-router model-request redaction, `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=FALSE`, no real PHI in MVP tests | Production requires ingest-time redaction before ADK session write, content-logging suppression, retention limits, access controls, and Cloud Logging/Trace review |
| Destructive redaction loses referential continuity across multiple patients or entities | Medium | Accepted for MVP | Product/Privacy | `[PATIENT_NAME]`, `[DOB]`, and `[MEMBER_ID]` replacement before model calls | Defensible for prior-auth summarization where the human reviewer has source documents; production may require pseudonymous stable tokens such as `[PATIENT_1]` |
| User over-trusts generated prior-auth summary | High | Mitigated | Product | HITL escalation, system card, README limits | Human process must enforce review |
| External provider stores or logs redacted context | Medium | Open | Legal/Privacy | Provider policy, BAA/contract review | Production requires provider review |
| Prompt injection attempts to bypass policy | High | Mitigated | InfoSec | 36-case deterministic red-team eval, safety-screening profile | Managed screening and live adversarial testing recommended before production |
| Synthetic invariance regression is too narrow for production fairness claims | Medium | Open | Responsible AI/Product | Structured prior-auth invariance regression compares requirement status, human review, and decision-boundary fields across synthetic demographic variants | Production requires broader cohorts, policy-specific fairness criteria, and clinical operations review |
| Fallback provider changes output behavior | Medium | Mitigated | Engineering | Fallback audit events, provider attribution | Monitor fallback rates and quality |
